# 标定一个新镜头并输出预演

这支脚本用输入素材的真实亮纹生成顺枝下行的脉冲，把多次触地回色限定在标好的可见地面上。适合先判断选对了哪棵树、打早还是打晚、有没有穿过前景。有四个可跟踪的共面路标时，脚本支持将波纹固定在路面坐标中；只标根部时，用随根点移动的屏幕椭圆近似。坡折、楼梯或不同深度的路面请切段重新标定。脚本生成无声的 8 位 H.264 预演。正式调色、声音、字幕和最终编码另行完成。

## 输入和运行

使用一段方向已烘焙、方形像素、正常速度的 SDR Rec.709 代理；预先稳定时，请在稳定后的代理上标点并用同一代理渲染。Log/HDR 素材先根据已知输入色彩变换得到这样的代理。这个脚本不会代做镜头解算、自动找树、旋转或 Log 转换。截取原片子段时，同时将标注时间平移到截取后第一张显示帧。

在带有 Python 3.10 或更新版本的环境中准备依赖。以下命令都在本技能目录运行。

```sh
python -m pip install "av>=16.1" numpy opencv-python-headless
python scripts/preview.py source.mp4 shot.json proof.mp4 --width 720
```

PyAV 所用 FFmpeg 需带 `libx264` 编码器。现成的 Python 环境已经能导入这些模块时可直接运行。输出按源长宽比缩小到不超过指定宽度，宽高取偶数。每张图沿用输入的显示间隔，第一张从零开始。将调查工具生成的九位小数 PTS 用作事件时间时，脚本按同一帧触发。若落点 H 真的位于两帧之间，第一张显示时间大于等于 H 的帧才有地面反馈。需音画严格同拍时，先从帧表选定实际触地帧的时间。程序完成并封装后才替换指定输出文件。

## 描一棵树

1. 先在树根清晰的一帧辨认同一棵树的树冠、可见高光和根部。将[示例标注](../assets/shot.example.json)复制为自己的 `shot.json`，把每个时间和顶点坐标换成新镜头实测值。示例用两个分叉和一条共用的下半段，以及一个遮挡地波的树干。
2. 取首帧、触地前、落地时和机位改变后几帧，在**相同裁切空间**测定顶点。点坐标用 px/(宽−1)、py/(高−1) 换算到 0–1，左上为 (0,0)。先锁住近景，顺着实际高光向根部排点，弯曲处加点。分叉汇流后，两条折线可共用一段下行顶点。两条路径长度差别很大时，预演可能在汇合处出现两个波头；正式合成要在共享树干重新安排到达时间。
3. 沿可见草地和实际铺地的边缘圈地面。把遮住草地的近景树干、花台、围栏另圈入地面遮挡，即使其颜色与地面很相近。第一棵树从画面边缘进入时，用仍可观察到的最早枝段开始。实际根部在画外的时段，可让能量离开画面；选择看得见落地点的镜头做地面击中预演，勿把画框边缘强行作为树根。
4. 为下一个可见树体添加事件。移动、遮挡关系变化或观察位置变化时补关键帧，保证老落点已恢复的地面随场景走。透视变化明显时把多次落点分开检查。完整回色可在最后一次地面传播后开启。

## 标注格式

每个形状都是关键帧列表，格式为 `[{"t":0.0,"points":[[x,y], ...]}, ...]`。时间单位为秒，严格递增；同一形状在每个关键帧保持相同顶点数量和次序。当前时刻位于两个关键帧之间时线性插值，超出两端时固定在最近的一帧。平面边缘和树干若在击中后继续移动，关键帧也须覆盖后续回色可见期。

| 字段 | 定义 |
| --- | --- |
| `ground` | 必需。整个可接收光的地面多边形，至少三点，顺时针或逆时针，避免自交。地面透过前景物体的部分用下列遮挡裁切。 |
| `ground_occluders` | 可选。多边形轨道的列表。只挡地波；一棵本身需要发光的近景树干也可以放这里。 |
| `occluders` | 可选。全场前景多边形轨道的列表，同时挡住枝光和地波，例如经过镜头的行人。自然场景完全回色时这些物体也恢复原片颜色。 |
| `plane` | 可选。平面尺寸和四点路面轨迹，见下节；省略时使用屏幕椭圆。 |
| `events` | 必需。事件列表，按 `hit` 由早到晚排列。双侧同时触地时，将两棵树分作独立事件并填同一 `hit`；两段路径与地面响应在同一帧中合成。 |
| `finish` | 可选两个秒数 `[a,b]`。a 至少是所有事件 `hit+spread` 的最大值；b 大于 a 且不超过片长。使整幅代理在这段时间由地面向上恢复原始颜色。省略时，未触达区域始终保黑。 |

每个事件包含以下字段。

| 字段 | 定义 |
| --- | --- |
| `id` | 可选树名，方便与声音 cue 表、绘制层名称对应。 |
| `start`、`hit` | 脉冲开始下行及到达地面的秒数，0 ≤ start < hit。前段沿枝较慢，后段向根部加速。 |
| `spread` | 击中后地面前沿从根部走到最大半径的时长（秒）。已染色区域取各场波的并集。 |
| `radius` | 没有 `plane` 时必需。地面椭圆最大横向半径，占整画幅宽度的比例。近、远处相同物理范围对应不同像素半径，应按镜头填写。 |
| `world_radius` | 使用 `plane` 时必需。最大地面半径，与 `plane.size` 采用同一长度单位。 |
| `depth_ratio` | 仅用于屏幕椭圆。可选，地面椭圆纵向半轴与横向半轴之比，范围 (0,1]，默认 0.34。按相机高度、地面坡度和远近调整。 |
| `root` | 根部轨道，每一帧形状恰好一个点。触地时应在可见地面的边界或内部。 |
| `paths` | 至少一条折线轨道的列表。每条折线至少两点，按树冠到根部排列，末点应在根部附近。用源片细亮纹限制能量。如果标在纯色墙或缺乏亮纹处，脉冲会变弱。 |
| `occluders` | 可选，只为这次事件起效的前景多边形轨道列表。例：近树挡住远树脉冲，但近树还会在自己的事件中发光。 |
| `audio` | 可选声音提示，画面预演忽略，适合与声音时间表共用一份标注。 |

## 让地面波纹固定在路上

[四点平面示例](../assets/shot-plane.example.json)可以用同一条命令运行。标注流程如下。

1. 在同一个平整路面上选四个形成**真实矩形**的固定特征，比如路砖四角、一个停车位的角或两排横缝与两条纵缝的交点。输入纵横的真实比例。示例 `"size":[3,6]` 表示横向宽 3、纵深长 6；使用米时 `world_radius:1.35` 就是 1.35 米。尺寸未知时可以用一块地砖作单位。任意四个不构成矩形的裂缝不能直接当成矩形的四角，否则波纹形状会失真。
2. 在 `quad` 中按**近左、近右、远右、远左**的顺序追踪这四个物理点。机位前移，近边与远边应有不同的屏幕位移。补关键帧直到固定点在中间帧也贴合；丢失四点、转入不同坡面、出现切镜时，应将该段拆开标注。优先选在所有待渲染时刻均可跟踪的特征。平面很斜、四点贴近地平线或顺序颠倒时，程序会拒绝退化矩阵并给出秒数。
3. 每个 `root` 取该树 `hit` 时的屏幕点，用这一刻的单应变换逆投影到地面，得到固定路面坐标。后续画面逐像素投回同一平面，计算与已落地各根的距离并取并集。此时触地后的根位置由平面决定，不依赖在每帧重画树根。四边形外、仍在同一平面及接收遮罩内的像素也可受光。接近地平线的无效投影和前景遮挡会从地波剔除；`ground_occluders` 仍需按落地时的遮挡关系单独跟踪。
4. 检查一个已染色的地砖角在镜头经过时是否仍然有颜色。若相机前移而圆心停在屏幕上，检查四点是否跟踪了同一组地标。近树遮住波纹时比较树干前后的颜色，可区分平面配准与前景遮挡的问题。最后的全景回色是另行安排的从下往上淡入，适合预演结束；它不是全景三维深度重建。

## 用预演做决定

抓取每次 `hit` 前后的相邻帧。下行速度的变化应先于地面返色；同一根枝上的能量应能被看见，边上那棵树依旧沉在暗部；下一个动作开始时，已亮地面应留在路上。在根部遮挡明显的镜头，把树干内外各采一小块，比较击中前后饱和度。在地波通过时前景树干提前返色，优先修地面遮挡和相机跟踪；纹理牵引不够时，先把路径对齐真正可见的亮纹，再考虑预演参数。全景最终回色以后，另检查人和建筑是否已经回到正确的曝光。

预演采用显示编码空间做快速混合，会保留素材色相，但不能代替 10 位或浮点成片的线性光合成。对于强视差、快速摇镜、台阶或遮挡交替的镜头，用通过预演的时间点和受光范围进入正式分层流程。
